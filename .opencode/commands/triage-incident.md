# Triage Incident

Structured emergency triage command for P0/P1/P2/P3 incidents.

## Usage

```
/triage-incident
/triage-incident "auth-service down 500 since 14:32 UTC"
/triage-incident "phishing campaign detected in finance inbox"
```

If no arguments: the agent asks for a 1-sentence summary and auto-prefills the triage ticket.

## Output: Triage Ticket

```markdown
# Triage Ticket - <auto-generated-id>

## Summary
<user input or inferred summary>

## Severity

| Level | Criteria | Action |
|-------|----------|--------|
| P0 | Active compromise, data breach, service unavailable to all users | Page on-call, CISO, SOC; immediate containment |
| P1 | Data leak / privilege escalation confirmed, single service down | SOC lead + eng on-call; 2h echo |
| P2 | Suspicious behavior, potential vulnerability, single user affected | Normal queue; 24h echo |
| P3 | Informational, no active impact, training/awareness event | Backlog; next sprint review |

## Scope

- **Affected systems**: ...
- **User impact**: ...
- **Data exposure**: ...
- **Attack vector** (if known): ...

## Immediate Actions

- [ ] Contain: network isolate / disable user / revoke token (per `field-kill-switch`)
- [ ] Preserve: screenshot, logs, network capture (Wireshark/tcpdump)
- [ ] Notify: SOC, IR lead, comms, legal (per incident-type matrix)
- [ ] Evidence: list paths, screenshot, log timestamps

## Owner Assignment

- **Primary owner**: @<role> (blue-team-operator / pentest-operator / dev lead)
- **Secondary**: @<role>
- **Comms owner**: @<role>

## ETA

- **Contain by**: <now + 15min / 1h>
- **Analysis start**: <contained + 30min>
- **Initial report**: <now + 2h>

## Next Steps

1. Contain (P0/P1 only)
2. Erradicate: identify IOCs, patch, rotate secrets
3. Recover: restore service, validate controls
4. Post-mortem: lessons learned, runbook update

## Rules

- Do not wait for perfect information before containing known-bad indicators (P0/P1)
- Preserve evidence before destroying it
- Communicate status every 30 min until contained
- Use `/complete-development` only for recovery implementation, not for triage
```

## Triage Heuristics

If the user is unsure about severity:

- Data exfil / phishing / credential theft → P1 minimum
- Service unavailable / ransomware → P0
- Single-user account takeover → P1
- CVE disclosed, no active exploit → P2

Use `blueteam-operator` agent to execute containment from this ticket.
