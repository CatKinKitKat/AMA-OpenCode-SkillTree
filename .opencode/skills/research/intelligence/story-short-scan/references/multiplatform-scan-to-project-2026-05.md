# 多平台扫书到项目：实战补充 2026-05

## 适用场景

用户要求同时扫番茄、七猫、起点，目标不是报告，而是扫完直接产出一个新故事项目包。

## 工作流

1. 先读项目目录现有命名，沿用中文文件名结构。
2. 番茄首页优先抓：巅峰榜、最近更新、官方短故事活动。
3. 七猫用搜索页抓细样本，关键词优先：`悬疑短篇`、`短篇`、`悬疑`、`密室`。七猫结果页可直接读：标题、分类、完结状态、字数、简介、更新时间。
4. 起点先做轻量探针。若浏览器显示 WAF 或 HTTP 返回 probe 页，只记录为「起点受限/仅作大盘参照」，不要把时间耗在绕过上；用番茄+七猫有效样本继续完成项目。
5. 把多平台数据写入 `_scan_<timestamp>/扫榜拆书记录.md`，再在项目目录写创作文件。
6. 交付前验证：项目目录 `.md` 文件数、`正文计划.md` 是否声明约 80,000 字且不超过 10 章、抽查非空。

## 推荐项目文件结构

```
projects/{中文标题}/
├── README.md
├── 扫书感悟.md
├── 简介.md
├── 大纲.md
├── 正文计划.md
├── 金手指.md
├── 世界观.md
├── 人物关系.md
├── 伏笔铺垫.md
└── 封面生图提示词.md
```

## 选题合成模式

- 番茄负责「大盘/新赛道/高概念」信号。
- 七猫负责「短篇简介/字数/情绪钩子/反转结构」样本。
- 起点若可读则补类型大盘；不可读则只保留探针结果。

有效组合公式：

`番茄高概念外壳 + 七猫短篇情绪钩子 + 一个职业身份 + 一个证据型金手指 + ≤10章案件推进`

例：

- 番茄短故事西方赛道 + 七猫画脸/太平间/替身样本 → 哥特雾港女验尸官。
- 番茄系统被国家征用 + 七猫复仇委托反噬 → 个人能力被机构滥用，女主从工具变审判者。

## Pitfalls

- 不要因起点 WAF 停工；该类任务的成功标准是产出项目，不是三站数据同量齐全。
- 不要把七猫长合集直接当短篇成品；应拆里面的短篇单元设定点。
- 不要只写市场报告；用户说「有灵感就新建文件夹」时，必须落盘项目文件。
- `封面生图提示词.md` 是当前项目约定文件名，优先于旧模板的 `封面提示词.md`。
