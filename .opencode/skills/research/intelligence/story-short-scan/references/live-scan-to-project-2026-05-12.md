# 多平台扫书到项目：2026-05-12 实战样例

## 触发场景

用户要求“番茄/七猫/起点扫书、拆书，新书且火和短篇；有灵感就落项目，8万字且不超过10章”。

## 有效流程

1. 先用番茄首页公开数据。
   - `https://fanqienovel.com/`
   - JS 提取 `a[href*="/page/"]`，重点看“最近更新”。
   - 选择低字数、近期更新、设定强的 2-3 本详情页。

2. 详情页抽取可迁移点。
   - 记录书名、字数、章节、更新时间、简介要点。
   - 强制写“可迁移点 / 不照搬点”，防止项目像单本改写。

3. 七猫/起点失败时只记本轮数据质量。
   - 七猫搜索页可能只有导航页脚。
   - 起点新书榜可能只有 iframe 空壳。
   - 不永久判死，不阻塞创作；用平台公式作参考即可。

4. 创作合成。
   - 至少取 2 个实时样本的元素交叉。
   - 再加 1 个平台公式维度：短篇强冲突、低阶反击、怪职业、单元反转等。

5. 落盘并验证。
   - 目标目录按中文项目名即可。
   - 必备文件：`README.md`、`扫书感悟.md`、`简介.md`、`大纲.md`、`正文计划.md`、`金手指.md`、`世界观.md`、`人物关系.md`、`伏笔铺垫.md`、`封面生图提示词.md`。
   - 用文件搜索验证 `.md` 数量，抽查 `正文计划.md` 必含“80,000字左右 / 10章 / 每章约8000字”。

## 本轮可复用模式

番茄实时样本：
- 遗物通灵 + 怪职业单元案。
- 灰域 + 失控哨兵 + 低阶向导逆袭。
- 低阶被嘲 + 异常能力反哺现实秩序。

合成题型：
- “被流放的低阶向导，用死者遗物安抚失控哨兵，揭开帝国战争账本。”

适合项目形态：
- 8万字 / 10章。
- 每章一件遗物、一个失控者、一段死者心声、一个公开打脸、一个主线证据。
