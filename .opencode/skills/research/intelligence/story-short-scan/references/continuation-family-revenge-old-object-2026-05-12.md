# Continuation scan-to-project: family revenge + old-object evidence

Use when a continuation prompt says to keep working toward the same scan/deconstruct/create goal after one project already exists.

## Durable pattern

1. Do not stop just because one project exists. If the user says continue, run a fresh scan and produce the next distinct project package.
2. Bias the new project away from recently created motifs. If recent outputs are corpse/forensic/monster/border/gothic, pivot to another hot short-form lane such as modern family revenge, inheritance, old-house, workplace, or relationship reversal.
3. Keep a scan artifact under `projects/_scan_<timestamp>/扫榜拆书记录.md`, then create a separate project folder with the usual project files.
4. Record unavailable platforms as evidence, but do not let them block the pipeline. Example: if Qidian returns WAF/empty iframe, note it and rely on readable Fanqie/Qimao data.
5. Verify project completion with a file-list check and a non-empty read of `正文计划.md` or `简介.md`.

## Source combination that worked

- Fanqie latest updates: use public homepage `最近更新` and official short-story activity signals. Good signals observed: `故宫修文物，系统帮我鉴赝品真！`, `万人嫌女配沉迷学习后，被抢疯了`, `风雪再难留，厉总他悔白头！`.
- Qimao search: `https://www.qimao.com/search?query=家庭复仇短篇` may initially show an empty shell. Type the query into the visible search box and click search. Then extract `document.body.innerText`.
- Useful Qimao sample cluster: `怨念的复仇(短篇）`, `复仇之剑，迟来的审判（短篇）`, `家庭的枷锁`.

## Resulting project archetype

Modern family revenge + old-object restoration + inheritance dispute.

One-line pattern:

> A low-status female old-object restorer returns for a funeral, is forced to accept a fake will, and uses ten inherited objects to expose a decades-old family exploitation scheme.
